# nbms_probe_player

Phase 3 probe player for NBMS 0.1.

This is not a full rhythm game player. It validates the package, resolves audio IDs, converts chart ticks to playback time, and can run a text-based realtime schedule.

## Usage

```text
python tools/nbms_probe_player/nbms_probe_player.py examples/converted_phase2/song.nbmh
```

Select a chart:

```text
python tools/nbms_probe_player/nbms_probe_player.py examples/converted_phase2/song.nbmh --chart main
```

Print every event:

```text
python tools/nbms_probe_player/nbms_probe_player.py examples/converted_phase2/song.nbmh --events
```

Run a realtime text schedule:

```text
python tools/nbms_probe_player/nbms_probe_player.py examples/converted_phase2/song.nbmh --realtime
```

Render mixed audio to WAV:

```text
python tools/nbms_probe_player/nbms_probe_player.py examples/converted_phase2/song.nbmh --render-wav out.wav
```

Render and play audio on Windows:

```text
python tools/nbms_probe_player/nbms_probe_player.py examples/converted_phase2/song.nbmh --play
```

Render encrypted audio:

```text
python tools/nbms_probe_player/nbms_probe_player.py examples/converted_phase4/song.nbmh --passphrase phase4-passphrase --render-wav out.wav
```

## What It Checks

- Header file can be parsed.
- Selected chart file can be parsed.
- `.nbma` can be opened as ZIP.
- `manifest.json` exists and can be parsed.
- Header audio archive hash matches actual `.nbma` bytes.
- Header chart hash matches canonical JSON hash.
- Every chart `audioId` exists in the audio manifest.
- Every manifest entry path exists in the archive.
- Each stored audio file hash matches the manifest entry hash.
- Timing events can be converted into milliseconds.
- Signed headers verify with Ed25519.
- Encrypted audio entries authenticate and decrypt with ChaCha20-Poly1305.

## Current Audio Status

The tool decodes FLAC entries from `.nbma`, mixes scheduled note and background-audio events into a temporary WAV file, and can play that WAV through Windows `winsound`.

The current FLAC decoder supports the prototype verbatim-subframe FLAC generated by `tools/bms2nbms`. A production player should replace this with a mature FLAC decoder and a low-latency audio mixer.

For Phase 4, encrypted `.nbma` entries are decrypted after archive hash validation and before FLAC decoding. Wrong passphrases fail authentication before any audio data is decoded.

## 確認内容

- Header fileをparseできるか
- 選択chart fileをparseできるか
- `.nbma` をZIPとして開けるか
- `manifest.json` が存在しparseできるか
- header audio archive hashが実際の `.nbma` bytesと一致するか
- header chart hashがcanonical JSON hashと一致するか
- chartが参照する全 `audioId` がaudio manifestに存在するか
- manifest entry pathがarchive内に存在するか
- stored audio file hashがmanifest entry hashと一致するか
- Timing eventsをmillisecondsへ変換できるか
- signed headersをEd25519で検証できるか
- encrypted audio entriesをChaCha20-Poly1305で認証・復号できるか

## 現在の音声状態

toolは `.nbma` 内のFLAC entryをdecodeし、note/background-audio eventをtemporary WAVへmixし、Windows `winsound` で再生できます。

現在のFLAC decoderは `tools/bms2nbms` が生成するprototype verbatim-subframe FLAC向けです。production playerでは成熟したFLAC decoderと低遅延audio mixerへ置き換える必要があります。
